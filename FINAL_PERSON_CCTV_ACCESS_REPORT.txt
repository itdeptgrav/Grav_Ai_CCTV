==========================================================================================

16. THE ADMINISTRATORS' KEY LINK (kept, on your instruction -- PASS)
==========================================================================================
  https://cctv.grav.in/?key=<key> and http://<laptop>:8000/?key=<key> open everything
  with no password, as before. Opened in a browser, the server answers with a signed,
  HttpOnly cookie and reloads the same page WITHOUT ?key= -- the key does not stay in the
  address bar, in bookmarks made afterwards, or in later links. The cookie is signed with
  a value derived from the key (it never contains the key), lasts 400 days, renews itself
  whenever a page is opened, and "Sign out" on the page removes it; changing the key
  signs every such browser out. Scripts and tools sending ?key= are answered directly.
  People never see the key: the CMS sends them to /sso?token=<a 90-second one-time
  token for that person>, which becomes a clean address with their own cameras only.
  Tests: 302 to the clean address + cookie; other query parameters kept; the cookie alone
  opens pages, all cameras, Settings, streams; renewed on page opens only; valid after
  days, not after 400 days or with another key; forged cookie -> 401; wrong key -> 401 and
  no cookie; sign-out clears it; a person signing in on the same browser replaces it.
  Real browser (throwaway server on 127.0.0.1:8014, synthetic video, a test key, no
  network): the key link landed on http://127.0.0.1:8014/ with 6 live tiles and
  "Administrator (key link)"; the key was nowhere in the page, its links or stream URLs,
  and page scripts cannot read the cookie; reload, Playback and Settings worked with the
  clean address; Sign out -> "Signed out", then the site asked to sign in; a wrong key was
  refused.                                                                         PASS
